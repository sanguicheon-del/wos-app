# Coding Standards

## General Principles
All work should be clear, consistent, maintainable, and production-ready. Code should communicate intent directly and avoid unnecessary complexity.

## Naming
- Use descriptive and consistent names.
- Prefer clear component, function, and variable naming over clever abbreviations.
- Follow existing project conventions for file and folder organization.

## Structure
- Keep logic organized and easy to follow.
- Favor small, focused components over monolithic implementations.
- Separate concerns clearly and keep responsibilities explicit.

## Quality Expectations
- Write readable, typed, and well-structured code.
- Avoid fragile patterns and unnecessary dependencies.
- Keep the implementation aligned with the project’s design and architecture standards.

## Review Standard
Changes should be easy to understand, safe to maintain, and appropriate for the product’s current maturity.
